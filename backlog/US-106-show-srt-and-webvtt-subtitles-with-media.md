# US-106 — Show SRT and WebVTT subtitles with media

**Status:** 📋 Ready (filed 2026-11-07 from the media-format survey) · **Epic:** Media formats ·
**Blocked by:** none · **Blocks:** none

## Story
As a JavaFX application developer,
I want to attach SRT and WebVTT subtitle files to a `Media` and get the cues that are active as it plays,
so that my application can show subtitles and captions in step with any media `javafx.media` plays.

## Problem
`impl/` is `modules/javafx.media/src/main/java/com/sun/media/jfxmediaimpl/`, `scene/` is
`modules/javafx.media/src/main/java/javafx/scene/media/` and `native/` is `modules/javafx.media/src/main/native/`.
- **No cue API.** The public `SubtitleTrack` only describes a track by ID, name, locale and metadata
  (`scene/SubtitleTrack.java:35-39`, `scene/Track.java:55-90`). Only AVFoundation reports one, for closed-caption tracks
  (`native/jfxmedia/platform/osx/avf/AVFMediaPlayer.mm:1170-1183`); GStreamer never does
  (`native/jfxmedia/jfxmedia_api.h:299-300`). Nothing in javafx.media delivers cue text or cue times (grep of
  `modules/javafx.media/src/main/java` for subtitle, caption and cue).
- **Timed events today.** Markers are a map from unique names to times (`scene/Media.java:332`), checked by a 40 ms
  poll (`impl/NativeMediaPlayer.java:1584-1591`, `:1646`), and each marker event carries its own media time
  (`scene/MediaPlayer.java:2438-2445`). The `currentTime` property is refreshed every 100 ms
  (`scene/MediaPlayer.java:2836`), while `getCurrentTime()` asks the player each time
  (`scene/MediaPlayer.java:1330-1338`).
- **WebVTT** is a W3C Candidate Recommendation Draft of 20 May 2026 (https://www.w3.org/TR/webvtt1/). A file is UTF-8
  with an optional byte order mark (§4.1); cues carry the settings `vertical`, `line`, `position`, `size`, `align` and
  `region` (§4.4) and the payload tags `c`, `i`, `b`, `u`, `ruby` with `rt`, `v` and `lang`, plus inner timestamps
  (§4.2.2); `NOTE`, `STYLE` and `REGION` blocks sit beside the cues (§4.1); §6 gives the parsing rules.
- **SRT** has no formal specification. A block is a counter, a `hh:mm:ss,mmm --> hh:mm:ss,mmm` line, text lines and a
  blank line; `<b>`, `<i>`, `<u>` and `<font color>` are unofficial; there is no standard encoding and the original
  tool defaults to Windows-1252 (https://en.wikipedia.org/wiki/SubRip).
- **API.** The README's goal is to extend the media API (`README.md:9`), and its non-goal on new public API covers
  only the `javafx.*` modules outside javafx.media (`README.md:20-21`).

## Constraints
- **New API** goes in javafx.media only, and this story lists it when it lands.
- **No new content type.** Subtitle files add nothing to `MediaManager.getSupportedContentTypes()`, so WebView's
  answers do not change (`modules/javafx.web/src/main/java/com/sun/javafx/webkit/prism/PrismGraphicsManager.java:155`).
- **Behaviour neutrality.** Playback, `SubtitleTrack` reporting and every other existing behaviour stay as they are.
- **Threading.** Cue changes reach the application on the FX thread; nothing changes the scene graph off it.
- **Untrusted input.** A subtitle file can come from anywhere; parsing it never hangs, and its time grows linearly
  with the file's size.
- **Licence rule** (`backlog/README.md`, "Media formats"): third-party Java code inside the jars is MIT, BSD, zlib, CC0,
  BSL-1.0 or similar; otherwise the code is written in-house from the specification. Every notice ships through US-075.
- **Java.** Java 27 final features only (no preview, no incubator such as the Vector API, no `var`). Production Java
  files are at most 900 lines (`wc -l`); tests and shims are exempt. Comments only for a non-obvious "why". GPLv2+CPE
  headers.
- **Tests.** Test files are generated by a command recorded next to them, never downloaded
  (`backlog/README.md`, "Port rules"). Agents never run `USE_ROBOT` or `tests/system`; any such run is the owner's.

## Out of scope
- Subtitle tracks embedded in MP4 or Matroska (US-107 leaves Matroska's out too).
- Drawing cues inside `MediaView`: the application shows the cues it gets.
- Interpreting the CSS of WebVTT `STYLE` blocks.
- Other subtitle formats (SSA/ASS, TTML, CEA-608) and writing subtitle files.

## Acceptance criteria
1. **Attach.** SRT and WebVTT files from any URI scheme `Media` accepts can be attached to a `Media`, before or after
   a `MediaPlayer` exists for it. Several files can be attached to one `Media`, each with a language. Attaching works
   for every `Media` that plays, audio or video, whichever back end plays it.
2. **Active cues.** At any moment the application can get each attached file's active cues: exactly the cues whose
   start ≤ t < end, where t is what `getCurrentTime()` returns, in file order when they overlap. Listeners hear of
   every change on the FX thread, at most 40 ms after the media time at which it happens.
3. **Follows the player.** Cues follow media time through pause, stall, rate changes, seek, cycle-count repeats and
   start and stop times. A cue that a seek jumps over is never reported as active, and outside the start and stop
   times none is active.
4. **WebVTT.** Files are parsed by the specification's parsing rules (§6). Each cue reports its identifier, times,
   text with its spans (`b`, `i`, `u`, `c` with classes, `v` with voice, `lang`, `ruby` with `rt`) and inner
   timestamps, and its settings (`vertical`, `line`, `position`, `size`, `align`, `region`). `REGION` definitions are
   reported; `NOTE` blocks are skipped.
5. **SRT.** Every block is parsed; `<b>`, `<i>`, `<u>` and `<font color>` are reported as the same spans and colour
   that WebVTT cues use.
6. **Encodings.** WebVTT is read as UTF-8, with or without a byte order mark. SRT is read as UTF-8 or UTF-16 when a
   byte order mark says so; otherwise as UTF-8 when the file is valid UTF-8, else in an encoding the application
   names, or as windows-1252 when it names none.
7. **Malformed files.** A file that is not SRT or WebVTT, or that cannot be decoded, fails with an exception naming the
   file, the line and the fault, and nothing of it is attached. An SRT block that does not parse fails the file the
   same way. Cues that the WebVTT parsing rules skip are skipped and reported with their line. A seeded mutation run
   over the test files, with its seed and count recorded, never hangs or crashes.
8. **API.** Each public type and member added to javafx.media is listed here with its `@since`, and its javadoc passes
   doclint. The package documentation describes both formats and the WebVTT subset of criterion 4.
9. **Nothing else changes.** The media module's tests pass with the counts of a run before the change, plus the new
   tests. All five CI legs are green.
